# AGENTS.md

## Cursor Cloud specific instructions

This is a self-contained Python ML project (Heart Disease Prediction). No database or external services are required. See `README.md` for the product overview and standard commands.

### Environment
- Python dependencies are installed into a virtualenv at `.venv/` (gitignored). The startup update script (`python3 -m venv .venv` + `.venv/bin/pip install -r requirements.txt`) keeps it current, so activate it or prefix commands with `.venv/bin/` (e.g. `.venv/bin/python`, `.venv/bin/uvicorn`, `.venv/bin/streamlit`).
- System Python is 3.12 and is PEP 668 "externally managed", so install into the venv rather than system/user site-packages.

### Services (both are independent entry points to the same models; neither calls the other)
- FastAPI backend: `.venv/bin/uvicorn api:app --host 0.0.0.0 --port 8000`. Test with `GET /`, `POST /predict`, or Swagger at `/docs`.
- Streamlit dashboard: `.venv/bin/streamlit run dashboard.py --server.port 8501 --server.address 0.0.0.0 --server.headless true`. Use the "Prediction" page to run a prediction end to end.

### Gotchas
- The committed models (`dt_model.pkl`, `rf_model.pkl`, `knn_model.pkl`) were trained with scikit-learn 1.8.0 while `requirements.txt` is unpinned (currently resolves to 1.9.x). Loading them emits `InconsistentVersionWarning`; predictions still work correctly. If you need to silence the warning or guarantee exact reproducibility, pin `scikit-learn==1.8.0` in `requirements.txt` (or retrain via `notebook.ipynb`).
- The `.pkl` model files are prerequisites for both services; they are committed to the repo, so no training step is needed to run. They are (re)generated by executing `notebook.ipynb`.
- No linter is configured. `python -m py_compile api.py dashboard.py` is a quick syntax sanity check.
- `README.md` shows `py -m uvicorn ...` (Windows launcher); on Linux use `uvicorn`/`python -m uvicorn` from the venv.
